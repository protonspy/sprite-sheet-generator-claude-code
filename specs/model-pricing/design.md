# Model pricing — design

## What changes

Four places, in this order:

1. **`scripts/fetch_model_schemas.py`** — new. It is what makes the other three
   reproducible, and it is the file `CLAUDE.md` and `core.json` have been naming all along
   without it existing. It reads two documents per model and writes `models.json`.
2. **`src/ssc/data/models.json`** — three video models added, and every entry gains a
   `price` object. Regenerated by the script, never hand-edited.
3. **`src/ssc/data/core.json`** — the concept mapping for the three added models. Hand-
   authored, as it already is, because no provider document says which field is this
   project's `--seed`.
4. **`src/ssc/cli/models.py` and `commands/model.py`** — `Model` carries the price;
   `model show` reports it; `model list` reports whether one is known.

Then the shipped texts: `src/ssc/data/harness/{claude,codex,opencode}/` and the four
`src/ssc/data/skills/sprite-*/SKILL.md`.

## Data

### The price, in `models.json`

```json
"price": {
  "text": "For **5s** video your request will cost **$0.35**. …",
  "fetched": "2026-08-13",
  "source": "https://fal.ai/api/models?keywords=kling"
}
```

`text` is the provider's `pricingInfoOverride`, byte for byte. `null` for the whole object
where the provider publishes none (R2.5) — the key is present and null, never absent,
because absent and "no such thing" read the same to a reader and mean different things.

**No parsed amount, and no field that looks like one.** Fal writes the price as prose, in a
different billing shape per model: per image with resolution multipliers (Nano Banana 2),
per token with a `quality` lever (GPT Image 2), per second by resolution (Grok 1.5), a flat
first five seconds then per second (Kling), per second *and* per thousand tokens with a
formula (Seedance 2.5). A parser over five shapes written by a marketing page is wrong the
first time one sentence is rewritten, and it is wrong silently — the number still renders,
the invoice is what disagrees. `budget.py` already records what the provider charged, per
call, which is the number that is true (R2.4, R2.6).

### `size` is `null` for all three added models

Not an oversight, and not the same fact three times. `gen.py`'s `ratio` shape needs a field
that *enumerates* its ratios, and none of the three has one: Grok 1.5 and Kling have no
`aspect_ratio` field at all, and Seedance 2.5 has one that is a free string defaulting to
`auto`. Recording a `ratio` shape anyway would make `--size` raise `size-unknown` on the
first call rather than at review. `null` is what `core.json` already means by "the model
has no such concept" — `--size` refuses instead of dropping the value silently, and
`--opt resolution=720p` still reaches the model through the raw path, checked against the
schema like any other option.

### `fetched`, and why a date rather than a timestamp

The file is committed, so the question a reader has is "how stale is this" measured in
days, not seconds. A timestamp would also churn the diff on every refresh for entries whose
text did not change.

## Boundaries and contracts

### Two provider documents, one file

| Document | Gives | Auth |
|---|---|---|
| `https://fal.ai/api/openapi/queue/openapi.json?endpoint_id=<id>` | `input_schema`, `about`, `category`, `documentation_url` | none |
| `https://fal.ai/api/models?keywords=<term>&size=100` | `pricingInfoOverride`, `title` | none |

Neither needs credentials (R3.5), which is why the refresh is a script anybody can run and
not something holding a key. The listing is searched by keyword and filtered to the exact
`id`, because it has no by-id route — `…/api/models/<id>` returns the site's 404 page.

### The script does not invent

An endpoint whose document fails to fetch keeps whatever `models.json` already has for it,
and the script says so and exits non-zero (R3.4). The alternative — dropping the entry —
turns one bad network minute into a registry that silently lost a model, and the failure
shows up as `unknown-model` on a workspace that was working yesterday.

### `model list` reports a boolean, `model show` reports the text

`list` is a table of everything; a paragraph of Markdown per row makes it unreadable. It
carries `"priced": true|false` so an agent can see which rows have something to read, and
`show` is where the sentence is (R2.2, R2.3).

## The shipped texts

The instruction file gains a **Choosing a model** section, and each `sprite-*` skill gains
the model and options for its own generating steps. What goes in them is a rule with an
axis, not a table of prices — a price copied into prose is a second record of a fact that
already lives in `models.json`, and it is the copy that goes stale.

The axis is the property of the work that multiplies the call: **how many** (`count`),
**how big** (`size`), **how good** (`quality`), and for video **how long** (`seconds`).
Those are four of the eight core concepts and they are already the ones `CONCEPTS` singles
out. So the guidance is: name the default model, name which of those four this step moves,
and say what to set when the work is small against when it is not — with `ssc model show`
as where the price for that choice is read (R4.1, R4.2, R4.4).

Every endpoint named in a shipped text is one the registry carries, and a test pins that
(R4.5) rather than a reviewer noticing.

## Alternatives considered

**Parse the price into an amount.** Rejected above: five billing shapes, prose source,
silent wrongness, and a real number already available from `budget.py` after the call.

**Fetch the price at run time instead of committing it.** Rejected. `models.json` exists
because a registry that needs the network is a registry that fails when the network does,
and `models.py` already treats the shipped copy as the fallback for exactly that reason.
A price is worth less than a schema, so it earns less network.

**Make the added video models the default.** Not this leaf's call — the default for `video`
stays `xai/grok-imagine-video/image-to-video` (R1.2). Grok 1.5 is a different endpoint at
roughly 1.6× the 480p rate, and switching what every existing workspace pays for is a
decision to take deliberately, not as a side effect of adding a model.

## Risks

**The listing's keyword search is the only way in.** If Fal changes that route, the refresh
loses the price half and keeps the schema half. That degrades to `price: null` on new
entries rather than to a wrong price, which is the direction to fail in.

**Five prices are transcribed at one moment.** They are stamped with `fetched` for exactly
that reason, and R2.6 makes every reader carry the sentence saying so.
