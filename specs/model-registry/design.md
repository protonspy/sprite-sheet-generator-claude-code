# Model registry — design

## What changes

Serves R1.1 to R1.5, R2.1, R2.2, R2.3.

`cli/models.py` for the registry and the check, `cli/commands/model.py` for `ssc model
list|show`, and one new hand-authored data file beside the fetched one.

**The shipped copy is the fallback, never the source.** `src/ssc/data/models.json` already
exists — task 0.7 fetched it from Fal's per-endpoint OpenAPI documents, which are public and
unauthenticated. A registry hard-coded in the package would be stale the week after Fal adds
a model, and stale *quietly*, so the reader tries the provider first and falls back, and says
which it did (R1.5). A caller debugging a rejected option needs to know whether it was
checked against today's schema or last release's.

**The fetch is injected, not imported.** `models.load()` takes the thing that fetches, and
the default is the one that uses the network. Nothing in the test suite reaches the internet
and nothing needs to: the shipped copy is a real schema, so the fallback path is the one the
tests exercise, and it is also the path that matters when Fal is down.

**Validation walks the schema, not a table.** The OpenAPI `properties` map carries `type`,
`default`, `enum`, `minimum` and `maximum` per field, and `anyOf` where a field is nullable.
That is enough to answer R2.1 and R2.2 without this project restating anything a model
declares — which is the point, since a restated table drifts silently.

## Boundaries and contracts

Serves R2.3, R2.4, R3.1, R3.2, R3.3.

**The normalised core is its own file, `src/ssc/data/core.json`, and that is deliberate.**
`models.json` is regenerated by `scripts/fetch_model_schemas.py`; a hand-authored mapping put
inside it would be destroyed by the next refresh. So the mapping lives beside it, keyed by
endpoint, recording each core concept as either the model's own field name or an explicit
`null` meaning *this model does not have this*:

```json
"fal-ai/gpt-image-1.5": {
  "prompt": "prompt",
  "seed": null,
  "size": {"kind": "enum", "field": "image_size"}
}
```

`null` is the load-bearing value. `seed` exists on Nano Banana 2 and does not exist on GPT
Image 1.5, so `--seed 7` must not be quietly dropped for one and honoured for the other —
R2.4 makes it a refusal, because a caller who asked for reproducibility and did not get it
has no way to find out except by running twice.

**A test pins the mapping against the schemas.** Every non-null field named in `core.json`
has to exist in that endpoint's `properties`. That is what keeps a hand-authored file honest
against a fetched one, and it fails at the refresh rather than at the first paid call.

`size` is a shape rather than a field name because the models disagree about the question and
not merely the spelling: an enum of three literal sizes on GPT Image 1.5, an aspect ratio plus
a resolution tier on the other two. `gen-fal` reconciles a layout against that, and this is
the form it needs to read it in.

**Which model runs comes from `ssc.yaml`, and a kind may override it.** `Profile` gains
`image_model` and `video_model`, empty by default meaning "whatever the workspace says" — a
delta against `specs/asset-kinds/`, which is that spec's mechanism working rather than a hole
in it. A configured model nobody knows is a refusal at exit `1` rather than a fallback to a
default: silently generating with a different model than the one configured is the same class
of failure as silently dropping an option.

## Risks

**The live schema is trusted, and that is the deal this design makes.** The fetched schema
*is* the acceptance check that stops a money leak, so a response that is subtly wider than
the real one — a raised `maximum`, a dropped `enum` — is indistinguishable from an honest
change and would be obeyed. Two things bound it rather than close it: the fetch is `https`
only, size-capped and on a wall-clock budget, and a schema that is empty or absurdly large is
not believed at all and falls back to the package. Neither makes a hostile response safe.
What makes it *survivable* is that the shipped copy exists and R1.5 says which was used, so a
call refused today and accepted yesterday has an answer rather than a mystery.

**A provider that changes a schema mid-flight.** The runtime read is authoritative, so an
option valid this morning can be refused this afternoon, correctly. What makes that
debuggable rather than baffling is R1.5 — the report says where the schema came from, so
"this used to work" has an answer.
